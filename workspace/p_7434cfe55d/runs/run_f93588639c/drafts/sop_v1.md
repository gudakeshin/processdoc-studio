# Complete Run

## Purpose

The Complete Run process establishes a structured workflow for finalizing project deliverables through systematic quality validation and remediation. This process ensures that all outputs meet established standards before release, reducing the risk of defects reaching stakeholders. By combining quality assurance assessment with guardrail validation, the process owner can confidently confirm that the run is production-ready and compliant with organizational requirements.

## Scope

This process covers the final validation phase of project execution, including user intent confirmation, quality assurance testing, remediation of identified issues, and guardrail compliance verification. The scope encompasses all activities performed by the Process Owner to assess and improve deliverable quality before completion. The process applies to all project runs requiring formal quality gates and does not include pre-execution planning or post-delivery support activities.

## Roles and Responsibilities

- **Process Owner**: Responsible for executing all steps in the Complete Run process, including updating user intent, conducting QA assessments, applying remediation measures, and verifying guardrail compliance. The Process Owner has authority to approve or reject run completion based on assessment outcomes and must document all decisions and remediation actions taken.

## Procedure

1. **Update user intent to complete run** — The Process Owner reviews and confirms the original user intent for the run, ensuring that all project objectives remain aligned with stakeholder expectations. This step validates that the scope, deliverables, and success criteria have not changed since project initiation and establishes the baseline for quality assessment.

2. **Execute QA assessment** — The Process Owner conducts a comprehensive quality assurance evaluation of all deliverables, outputs, and work products generated during the run. This assessment applies defined quality criteria and standards to identify any defects, inconsistencies, or gaps. The QA outcome is documented and communicated to inform the next step.

3. **Apply QA remediation** — Upon identification of QA failures, the Process Owner executes corrective actions to address defects and quality issues. This step includes root cause analysis, implementation of fixes, and validation that remediation efforts resolve the identified problems. The remediation outcome is recorded for audit and compliance purposes.

4. **Execute guardrail assessment** — The Process Owner performs a final compliance check against organizational guardrails, policies, and control requirements. This assessment confirms that the run adheres to all established governance standards and risk mitigation controls. The guardrail outcome is documented and serves as the final gate before run completion.
